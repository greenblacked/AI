# Weekly review records

Loads when a written weekly review is read or edited. The review exists to change next
week's decisions, so the record has to show which decisions, and which were refused.

- Start the file with `# Week of [date]` and keep the headings of the
  `weekly-review-record.md` template, so a later review can find what was committed.
- Hold 3 to 5 commitments under `## Commitments`. A sixth is a wish: move it to the
  not-doing list or drop it.
- Make each commitment checkable on Friday by someone other than its author: an outcome and
  the time it is blocked, not "work on the migration".
- Keep a `## Consciously not doing` section, with a reason and a reconsider date for each
  item. An empty list means nothing was chosen against, which is rarely true.
- Read last week's file before writing this one, and record the cause of every gap
  (avoidance, estimate, interruption, dependency, deprioritised), not only the outcome.
- Do not add a collection or filing pass to the record. Notes from reading belong in
  `learning-notes`.
