# D2

Read this before writing a `.d2` file, or when `d2` fails or a label comes out wrong. Everything here was run against D2 0.8.1 on Linux; the D2 project's README (github.com/d2lang/d2, licence Mozilla Public License 2.0) is the primary source for the layout engines and export formats.

## When it is the right tool

An architecture diagram with many nodes and containers, committed as SVG, where Mermaid's layout would tangle. D2 is a single command-line program that renders SVG, PNG, GIF, PDF and PPTX, and in 0.8.1 bundles two layout engines: `dagre` (the default) and `elk`. `tala` is a separate plugin there; D2's changelog marks it as bundled only from 0.9.0, so raise the pinned version before relying on it. Pick one with `--layout=NAME` or the `D2_LAYOUT` environment variable; `d2 layout` lists what the installed build has. Try `elk` when `dagre` crosses too many edges. Naming an engine the build does not have exits 1 and lists the ones it does.

Install it from a release or with `go install github.com/d2lang/d2@v0.8.1` (the version this file was checked against; raise it deliberately). The README also shows an install script piped to a shell; download and read a script before running it instead, and pin the version you install so that CI and your machine render the same bytes.

## Commands

```bash
d2 validate diagram.d2                 # parse only; exit 0 or 1
d2 fmt --check diagram.d2              # exit 1 when the file is not canonically formatted
d2 fmt diagram.d2                      # rewrite it canonically
d2 diagram.d2 diagram.svg              # the committed render; exit 1 on a compile error
d2 diagram.d2 /tmp/diagram.png         # a throwaway copy to open and look at
d2 --omit-version diagram.d2 diagram.svg   # leave the D2 version out of the SVG
```

`d2 validate` and `d2 diagram.d2 out.svg` both exit 1 with a message that carries the line and column (`2:4: maps must be terminated with }`). Rendering twice with the same D2 version produced byte-identical SVG, so a CI job can regenerate every diagram and fail on `git diff --exit-code` when a committed render is stale, as long as the version is pinned.

## Pitfalls

- **An unquoted `#` starts a comment, and the rest of the label vanishes without an error.** `a -> b: has # hash` validated and rendered with exit 0, and the edge label read `has`. Quote any label that contains `#`.
- **A dot in an unquoted key is nesting, not part of the name.** `orders.api -> db` created a container `orders` holding a node `api`. For a literal dot, quote the key: `"orders.api" -> db`. This also means `shop.web` is how you point at a node inside a container, which is useful on purpose and a surprise by accident.
- **A semicolon separates statements.** `x: a;b` produced two nodes, `a` and `b`. Quote a label that contains one: `"x; y"` stayed one label.
- **Reserved words fail loudly in an edge.** `label -> db` and `style -> db` exit 1 with `reserved keywords are prohibited in edges`. Use another key and put the text in the label.
- **A colon inside the label.** Quote the label, as in `web -> api: "HTTPS: JSON"`, so the colon is plainly text.
- **Characters that look like markup.** `a: "R&D <team>"` rendered as the literal text in the SVG; quoting is enough.
- **`d2 fmt --check` fails on spacing.** `{ shape: cylinder }` was rewritten as `{shape: cylinder}`. Run `d2 fmt` and commit the result so the check does not become noise.

## Sequence diagrams

Setting `shape: sequence_diagram` on the diagram or on a container makes its edges read in order, top to bottom:

```d2
shape: sequence_diagram
client: "Client"
api: "Orders API"
client -> api: "POST /orders"
api -> client: "201 Created"
```

## A minimal file to start from

```d2
# nodes: max N   - the cap, written before the first node
direction: right
shop: "Shop" {
  web: "Web app"
  api: "Orders API (v2)"
  db: "Orders DB" {shape: cylinder}
  web -> api: "HTTPS: JSON"
  api -> db: "SQL"
}
customer: "Customer" {shape: person}
customer -> shop.web: "browses"
```

Replace N in the comment with the cap you chose for this diagram.
