# Moderation templates

Read this at steps 2 to 4 when drafting rules, the ladder and the log.

## Contents

- Rule format
- Ladder table
- Log columns
- Appeal reply
- Raid mode checklist

## Rule format

```text
R3. Do not post other people's private information.
Why: it cannot be undone and it exposes members to harassment off the platform.
Examples: home addresses, workplace details, private messages shared without consent.
Skips the ladder: yes (removal and ban on first occurrence).
```

Keep one rule to one behaviour so the log can cite it unambiguously.

## Ladder table

| Step | Typical use | Visible to | Expires |
| --- | --- | --- | --- |
| 1. Note | First minor slip, tone | Moderators | After 30 days |
| 2. Warning | Repeat of a noted behaviour | Member, moderators | After 90 days |
| 3. Timed mute | Heat of an argument, repeated warnings | Member, moderators | At end of mute |
| 4. Removal | Serious or persistent breach | Member, moderators | Reviewed on request |
| 5. Ban | Skip behaviours, removal ignored | Member, moderators | Appeal only |

The periods are examples; set your own and write them next to the table.

## Log columns

| Column | Content |
| --- | --- |
| Date and time | When the action was taken |
| Moderator | Who acted; "automation" and the rule name for bot actions |
| Member | Account identifier |
| Rule | Number cited |
| Step | Ladder step used, and whether a step was skipped and why |
| Evidence | Link or quoted text; keep a copy if the platform allows deletion. For suspected child sexual abuse material, never copy or screenshot it: record only the message ID or link and the time, and report through the escalation path |
| Outcome | Action taken and the message sent |
| Appeal | None, open, upheld or overturned, and the reviewer |

## Appeal reply

State the decision, the rule, what changes (or does not) and the date any restriction ends. Do not argue the original case again, and do not name the reporting member.

## Raid mode checklist

1. Lock sending for accounts newer than a stated age, and turn on slow mode in public channels.
2. Pause invite links and remove invites created during the wave.
3. Remove the spam in bulk using the platform's tools, and log the count rather than one row each.
4. Ban the accounts, keeping a list of the account identifiers or join times for the summary.
5. Turn raid mode off by hand once the join rate returns to normal, and note the time.
