# Stress-testing candidate features

## A worked table

Suppose a game with three pillars: "Legible over spectacular", "Short sessions over deep ones", "Consequence over comfort".

| Feature | Serves | Strains | Verdict | Rests on |
| --- | --- | --- | --- | --- |
| Screen-filling boss death animation | none | Legible over spectacular | Redesign: keep the beat, shorten it and keep the arena readable | Legible over spectacular |
| Save anywhere | Short sessions | none | Keep | Short sessions over deep ones |
| Rewind the last ten seconds | none | Consequence over comfort | Cut | Consequence over comfort |
| Daily streak reward | none | Short sessions (rewards daily return, not a short visit) | Redesign: reward a finished run, not a login | Short sessions over deep ones |
| Photo mode | none | none | Gap: either a missing pillar or filler; decide which before building | none |

## Mixed cases

A feature that serves one pillar and strains another is not automatically kept. Ask whether the strained pillar is the one the game would be recognised by. If so, redesign; if the strain is mild and the service is strong, keep and record the strain as a known cost, with the milestone at which it is rechecked.

## When the output is a pillar, not a verdict

If three of the five features cannot be placed, or the same good-looking feature keeps landing on a gap, the set is incomplete or mis-worded. Draft the missing trade-off, run step 3 on it, then re-run the five. Do not widen a pillar to admit a feature; a wider pillar excludes less and the next five will not be decided by it either.

## Who decides

A verdict is a proposal until the owner of pillars confirms it. Record the owner at the top of the table, and the date. A cut feature is revisited only when its form changes or a pillar does, not when the person who proposed it asks again.
